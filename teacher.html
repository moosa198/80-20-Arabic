Teacher workspace

See progress, not just completion.

Create a class, give each learner an individual access code, and see weekly completion, recall checks, source-page readiness and their saved Qur’anic grammar explanations. Each teacher account is isolated to its own classes.

1. Connect a classroom data store

This static website needs a Supabase project for secure cross-device progress. Create the project, run classroom-schema.sql in its SQL Editor, and enable Anonymous Sign-Ins for student sessions. Use only the public anon/publishable key in this page—never the service_role key.

The learner setup file contains only the project URL and public key. Give students their class code and personal learner code separately. Do not post learner codes publicly.

Sign in to see your classes and learner progress.

What this dashboard stores

Teachers: email/password authentication, class names and roster.

Learners: display name chosen by the teacher, an individual access-code hash, pseudonymous browser session, and learning progress.

Progress: completed weeks, recall activity, source-first check, selected Arabic words and the learner’s explanation. Teachers can view only their own classes.

Minimise data: use first name plus initial or a teacher-assigned identifier where suitable. Do not enter medical, family or other sensitive information.

Learner evidence

Classroom data is stored in the Supabase project you configure—not in the GitHub repository. RLS policies restrict teachers to their own classes and students to their own progress. Before using this with minors, the madrassa should approve the service, give students/parents age-appropriate privacy information, define retention/deletion, and confirm who is responsible for the data.
