# 80/20 Arabic

**See the Qur’an. Understand the structure.**  
A 31-week source-book-first learning product for students who are memorising the Qur’an and want to understand a grammatical concept from FSTU before applying it to a 15-line Qur’an page.

## What students can do

- Follow the **31-week sequence** through foundations, relationships, connected meaning and independent reading.
- Work through three **Al-Fātiḥah retrieval checkpoints** in weeks 8, 16 and 24.
- Learn seven lexical words in each teaching week. High-frequency grammatical/function words have their own recurring box and review set.
- Review Qur’an vocabulary, high-frequency Qur’an words, and grammar terms in English ↔ Arabic.
- See technical terms paired with English, fully vowelled Arabic and subtle scholarly transliteration: **Pronoun — ضَمِيرٌ — ḍamīr**, **Nominal sentence — جُمْلَةٌ اِسْمِيَّةٌ — jumlatun ismiyyah**, **Prepositional phrase — جَارٌّ وَمَجْرُورٌ — jārr wa-majrūr**, **Emphasis — تَوْكِيدٌ — tawkīd**.
- Complete Sabaq, Sabaq Sipara / Sabqi and Dhor / Dawr before optional Arabic work; defer Arabic whenever Hifz needs attention.
- See a digital 15-line Madina Qur’an page without uploading PDFs, and tap individual Arabic words to record recognition evidence.
- See only the FSTU page numbers assigned for that week; each source preview opens at its assigned printed page. Students study the source first, complete a source-concept question and teach-back, and only then unlock the Qur’an application stage.
- Open the official Al-Qalam Institute FSTU Ṣarf (صرف) and Naḥw (نحو) resources from the assigned-page previews.
- Use the core Arabic listening playlist as part of the weekly lesson, with the bonus playlist available for repeated practice.
- Complete the source concept check before application, select word(s) on the Qur’an page, choose a grammatical role with vowelled Arabic and transliteration, explain the clue, and save multiple attempts. The app does **not** automatically grade complex grammatical analysis; a teacher checks uncertain or disputed parses.
- Build transfer through progressively less scaffolding and an independent week-31 page analysis.
- Track learning locally and export a backup; optionally join a class so progress syncs across devices and a teacher can review weekly completion, concept checks and written recognition evidence.

## Pedagogical approach: source → teach back → Qur’an → retrieve → transfer

The teaching sequence is deliberately **source book first**. The source explains the concept and shows examples; the Qur’an page is the application step, not the place where a beginner is expected to infer a rule unaided.

1. **Source:** Read only the assigned FSTU page(s). Work through the definition, rule, worked example and relevant tarkīb (تَرْكِيبٌ, tarkīb). Do not read an entire textbook chapter if that week needs only one or two pages.
2. **Teach back:** Close the source and explain the idea in the student’s own words. Tick the source checks and answer the source-concept question correctly. The Qur’an stage remains closed until that self-check is passed.
3. **Apply:** Open the assigned 15-line Madina page. Match the source concept to actual Arabic evidence and select the relevant word or relationship.
4. **Explain:** Choose the English grammatical role, see its fully vowelled Arabic name plus transliteration, and justify the clue. This is evidence for teacher review; it is not automatically graded as fully correct syntax.
5. **Transfer:** Revisit the pattern later and identify it in another memorised passage. The three Al-Fātiḥah checkpoints in weeks 8, 16 and 24 are retrieval exercises, not new units; students must use another memorised page if a target feature is genuinely absent from Al-Fātiḥah.

The general 80/20 and early-real-text inspiration comes from the publisher’s [Arabic Acceleration Report](https://www.learnarabiconline.com/ArabicAccelerationReport.pdf). The exact `ArabicAccelerationReport2.0.pdf` URL supplied for the project could not be retrieved in this session. This is therefore a principled adaptation of the accessible report, not a claim to have followed version 2.0 line by line or to reproduce its outcome estimates.

The weekly lesson is designed for around 45 minutes. Hifz remains the priority; this optional Arabic supplement must never compete with memorisation or revision.

## Weekly learning sequence

Each teaching week follows **(1) assigned FSTU pages → (2) written/oral teach-back + source-concept check → (3) Qur’anic page → (4) listening and application → (5) saved evidence for review**. The adab reminder asks students to make wudhu before handling a physical Mushaf; there is no software gate for a digital page beyond the learning check.

## Learning rhythm

Between classes, use short revisits rather than cramming: a few minutes of vocabulary recall, a focused FSTU exercise, then find the same structure on a different memorised page. Adjust the amount to the students’ age and capacity. Accuracy and justified transfer matter more than speed on a first attempt.

The review scheduler uses simple self-ratings:
- **Again:** the answer was not recalled; return soon.
- **Hard:** recalled with difficulty; return sooner.
- **Good / Easy:** recall was stronger; increase the interval.

The “well-established” word count means a card has been answered successfully at least four times. It is a practical study signal, **not a formal measure of Qur’an comprehension**. Understanding must be checked by a teacher using fresh passages and Arabic evidence.

## Classroom tracking for other teachers

The Teacher Classroom portal is designed so each teacher can create and monitor only their own classes. Learners connect with a class code plus a personal access code. The dashboard reports completed weeks, source-readiness checks, concept recall, recognition attempts and learner explanations; teachers can inspect the evidence, reset a code, and export a class CSV.

**Central monitoring is optional and requires the madrassa to configure a Supabase project.** This repository cannot provision the school’s database or create a project key on the madrassa’s behalf.

1. Create a Supabase project controlled by the madrassa.
2. In SQL Editor, run [`classroom-schema.sql`](./classroom-schema.sql). It creates the class, student and progress tables, row-level security policies, and class-code RPCs. The learner’s access code is stored as a hash.
3. In Authentication settings, enable Anonymous Sign-Ins for learners. Keep teacher accounts email/password authenticated.
4. Open [Teacher Classroom](https://moosa198.github.io/80-20-Arabic/teacher.html), save the project URL and **public anon/publishable key**, and create a teacher account. Never place a Supabase `service_role` key in this static website.
5. Create a class and add learner display names. Download the learner code sheet immediately; personal codes are shown only once. Share the class code and each student’s personal code privately, plus the project setup file.
6. Each student opens Student Studio, imports the setup file, enters their class and individual codes, and connects. They can then work across devices; the teacher dashboard reads from the shared database.

The app stores progress locally first and syncs when connected. On a shared device, students must use **Disconnect this device** before handing it to someone else; this syncs, unlinks and clears local learner records. If a device is lost, the teacher can reset that learner’s code without deleting class progress.

Before using the portal with children, the madrassa must approve the service, provide students/parents with age-appropriate privacy information, define retention/deletion, and decide who is responsible for the data. Use pseudonymous display names where practical and do not store sensitive personal information.

The app and classroom portal use third-party services. The Qur’an renderer, Google Drive FSTU previews, YouTube, Google Fonts and Supabase require internet access and may receive normal network metadata. The service worker caches the app’s own files, but the source-page and listening experience is not fully offline.

## Printable workbook and automated quality checks

The in-app **Print full course workbook** creates a student copy with writing space and no answer key. GitHub Actions tests the rendered interface in Chromium before generating the PDF. Checks cover all 31 lessons, paired English/Arabic terminology, right-to-left Arabic, seven lexical slots per teaching week, Fātiḥah checkpoint behaviour, page/source references, recognition controls, mobile width and workbook page count. Screenshots and the content audit are stored as workflow artifacts.

## Maintain the bilingual terminology

The app’s terminology map lives in `TERMS` in `index.html`. Store every technical label as an English/Arabic pair; render Arabic in a separate element with `lang="ar"` and `dir="rtl"`. Do not concatenate English and Arabic into one mixed-direction heading.

## Scope

This is a practical teaching aid, not a replacement for a qualified teacher, reliable tafsīr, dictionary work or careful tarkīb. Vocabulary glosses are short recall cues rather than exhaustive lexical definitions. In the capstone, students choose words from a memorised page, justify their analysis and check any uncertainty with a teacher.
